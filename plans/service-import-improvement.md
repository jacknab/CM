# Service Import Feature Enhancement: Intelligent Category Matching & Auto-Creation

## Overview
Improve the AI-powered service import feature to intelligently match extracted services to existing categories and auto-create new categories when needed, supporting multiple salon types (nail, hair, spa, massage, etc.).

---

## Current State

**Location:** `artifacts/api-server/src/routes/serviceImport.ts`

**Current Workflow:**
1. User uploads PDF/images
2. AI extracts services + assigned categories (7 fixed categories for nail salons)
3. On publish: AI-assigned categories are validated against allowed list
4. **Limitation:** Services with unrecognized categories are skipped

**Issues to Fix:**
- No intelligent matching to existing store categories
- Cannot create new categories (hardcoded to 7 nail salon categories)
- Users lose services if categories don't match
- Doesn't adapt to multiple salon types

---

## Architecture Design

### 1. Category Matching Algorithm

**Approach:** Two-tier system with confidence scoring

#### Tier 1: Semantic Similarity Matching (AI-powered)
```
For each extracted service:
1. Get store's existing categories (retrieve from DB)
2. Send to AI: "Which category does this service belong in?"
   - Input: service name, service description, existing category names
   - Output: best_category (name) + confidence_score (0.0-1.0)
3. Decision logic:
   - confidence >= 0.85 → use matched category
   - confidence < 0.85 → proceed to Tier 2 or flag for new category creation
```

#### Tier 2: Fallback - Fuzzy String Matching
```
Use Levenshtein distance or similar-text algorithm:
- Match service name against category names
- If similarity >= 70% → assign to matched category
- If no match → flag for auto-category-creation
```

**Implementation Details:**
- Add helper function: `async matchServiceToCategory(serviceName, serviceDescription, existingCategories): Promise<{ categoryName: string; confidence: number }>`
- Reuse existing OpenAI API calls (no extra cost)
- Cache category list per store for performance

---

### 2. Auto-Category-Creation Workflow

**Trigger:** When service doesn't match any existing category (confidence < 0.85 AND fuzzy match < 70%)

**Process:**
```
1. Collect all unmatched services
2. Send to AI: "Suggest 3-5 logical category names for these services"
   - Input: list of unmatched service names
   - Output: array of suggested categories + descriptions
3. Validate suggested categories:
   - Name format (alphanumeric, hyphens, underscores)
   - Not duplicate with existing categories (case-insensitive)
4. Create categories in DB with metadata:
   - name: string (required)
   - storeId: number (required)
   - sortOrder: auto-increment
   - isAutoGenerated: boolean (true for AI-created categories)
5. Re-assign unmatched services to newly created categories
```

**UI Indicator:** Show which categories were auto-created in the review step so user can edit/rename if desired.

## Implementation Plan

### Phase 1: Backend Enhancements
**File:** `artifacts/api-server/src/routes/serviceImport.ts`

**New Functions:**
1. `async getExistingCategories(storeId: number): Promise<string[]>`
   - Fetch all category names for the store
   
2. `async matchServiceToCategory(serviceName: string, description: string | undefined, existingCategories: string[]): Promise<{ categoryName: string; confidence: number } | null>`
   - Use GPT to match service to best existing category
   - Return null if no match (confidence < 0.85)
   
3. `async suggestCategoriesForUnmatched(unmatched: ExtractedService[]): Promise<string[]>`
   - Use GPT to suggest new category names based on unmatched services
   - Return array of suggested category names
   
4. `async enrichAIResultWithCategoryMatching(aiResult: AIMenuResult, storeId: number): Promise<AIMenuResult>`
   - Main orchestration function
   - Calls matching logic for each service
   - Auto-creates missing categories
   - Returns enriched result with all services assigned to categories

**Modified Functions:**
- `processImportJob()`: Add call to `enrichAIResultWithCategoryMatching()` after AI extraction
- `POST /publish`: Simplified since all categories now exist

### Phase 2: Frontend Updates
**File:** `artifacts/booking/src/pages/setup/ServiceImportFlow.tsx`

**UI Changes:**
1. Review screen shows:
   - Services grouped by category
   - Confidence badges for each category assignment (High/Medium/Low)
   - Highlight auto-created categories with a "New Category" badge
   - Allow inline editing of category assignments
   - Allow rename of auto-created categories

2. Summary before publish:
   - X categories (Y auto-created)
   - Z services (with confidence distribution)

## Error Handling & Fallbacks

| Scenario | Action |
|----------|--------|
| AI matching fails | Fall back to fuzzy matching or create new category |
| No matching categories + auto-create fails | Mark services as "requires manual categorization" |
| Store has 0 categories | Create reasonable defaults based on extracted services |
| Duplicate category names (after normalization) | Merge into single category |

## Performance Considerations

1. **API Call Optimization:**
   - Batch AI requests where possible
   - Cache existing categories per store session
   - Use parallel matching for multiple services (Promise.all)

2. **Efficiency:**
   - Confidence score threshold: 0.85 (tunable)
   - Fuzzy match threshold: 70% (tunable)
   - Limit AI suggestion calls to once per import batch
